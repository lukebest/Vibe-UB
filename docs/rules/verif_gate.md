## 0. 流水线与本地入口

每次 `push` / `pull_request` 跑 `.github/workflows/gate.yml`。CI **只**调用 `scripts/gate/*.sh`。本地：

```
make gate
```

与 CI 同一套脚本。快速综合的 QoR 趋势归实现（`scripts/impl/quick_synth.sh`），**不**拦合入；本门禁的 `synth-check` 只判过 / 不过（latch / 多驱动 / 组合环）。

工具版本从仓库根 `TOOLCHAIN.lock` 读。装不到锁定版本时，job 日志打印 `locked=` 与 `actual=`，并写明 MISMATCH，不静默当成已锁定。

机器可读名单在 `gate/`（与 `waivers/` 同一套批准约束：`approver` 必须是 `waivers/approvers.yml` 里的守门人）。

## 0.1 三线与自动发现

层名从目录发现，脚本不写死 `pcs` / `dll` / `lmsm` / `csr`。B/C 以后加 `pycircuit/<layer>/`、`rtl/<layer>/`、`formal/<iface>/`、`tb/<layer>/` 即可被扫到。

| 线 | 检查 | 路径 |
| --- | --- | --- |
| **A** | emit + `git diff rtl/` + hooks 存在 + 端口一致性 + PRODUCT≡HOOKS | `pycircuit/<layer>/` → `scripts/emit_rtl.py` → `rtl/<layer>/` 与 `rtl/<layer>/hooks/` |
| **B** | lint / synth-check / cdc-rdc | `rtl/<layer>/`（含 `hooks/`）；白名单手写与已登记桩照常跑 |
| **C** | `formal/<iface>/*.sby` | 每接口自带小桩，无产品 RTL 也能跑。C 线 SRAM 宏未选型时用行为桩，见 §1.2 |

`emit_rtl.py` 不存在时 skip emit+diff，并打印原因；手写扫描、hooks、等价仍跑。

## 1. 共同失败判据

每条检查产出 findings。每条 finding 先分类，再看豁免：

| 栏 | 判定 | 门禁 |
| --- | --- | --- |
| 新叶子 | 不在 `gate/legacy.txt`，或文件头表明由 pyCircuit 生成 | **拦截**（未豁免即 FAIL） |
| D10 legacy | 路径匹配 `gate/legacy.txt`，且不是 pyCircuit 重写 | **只报告不拦截** |
| report-only | 桩时序 vs MODULE_INVENTORY 等（§1.2） | **只报告不拦截** |

D10 判定见 [DECISIONS.md](../DECISIONS.md) D10。`gate/legacy.txt` 是可配置名单（精确路径或 glob）。从名单删路径 = 该文件改为拦截，须守门人书面批准（CODEOWNERS 覆盖 `/gate/`）。

pyCircuit 生成物即使暂时仍写在旧路径，只要文件头含 `GENERATED from pycircuit` / `Generated by`，一律当新叶子拦截。

豁免见 §9。未豁免的新叶子 finding 使对应 job 失败。legacy / report-only 栏写入报告，不构成 FAIL。

### 1.1 白名单手写 SV（`gate/handwritten.yml`）

与 `waivers/` 同一套约束：每条写文件路径、原因、批准人（守门人）。今天只有 `rtl/common/ub_rst_sync.sv`（复位同步器，CODING_STYLE §3，SPEC §4.2，D6）。

清单上的文件：

- 不参与 emit 一致性检查和「必须有 hooks 网表」检查
- eqy / Yosys 等价跳过（`TEST_HOOKS=0/1` 共用同一份）
- lint、综合检查、CDC/RDC 照常跑
- CDC 把它当作合法的复位同步单元（可含异步复位敏感表，计入 sync cell）

不在清单上的手写 `.v` / `.sv` 出现在 `rtl/` 记 `HANDWRITTEN_UNLISTED`。新叶子拦截；若路径同时在 `gate/legacy.txt` 则只报告。白名单单元本身不进 `legacy.txt`，其上的 lint / CDC finding 按新叶子拦截。

### 1.2 桩 / 黑盒（`gate/stubs.yml`）

C 线用行为模型桩代替尚未选型的 SRAM 宏。每条写路径、替代对象、原因、守门人批准（与手写清单同一套约束）。

- **已登记：** lint、综合检查照常跑
- **未登记**的桩或黑盒（`(* blackbox *)` / `(* stub *)`、文件名 `*_stub` / `*_blackbox`、目录 `stubs/` / `blackbox/`）：`STUB_UNLISTED`，**拦截**

桩时序以 **MODULE_INVENTORY** 存储需求行为为准（架构所有；落地路径优先 `docs/arch/MODULE_INVENTORY.yml`）：

| 项 | 约定 |
| --- | --- |
| 读延迟 | `read_latency`（addr→data 的 `core_clk` 拍数） |
| 端口 | `1RW` 或 `1R1W` |
| 同地址冲突 | `read_old` 或 `read_new` |

自动对照可以先做成 **report-only**（`STUB_TIMING`）。清单尚未有条目、库存文件尚未落地时，打印原因并跳过对照。

## 4. cdc-rdc

规则写在 `scripts/gate/cdc_rules.yml`，可加时钟名、同步器单元、新 check id，不必改 workflow。`gate/handwritten.yml` 上的模块并入异步复位白名单与 sync cell。

## 9. 豁免流程

任何检查豁免都需要守门人**书面批准**（[TEAM.md](../TEAM.md) §4）。不得自己批自己的草稿。

1. 在 `waivers/pending/` 写 YAML 草稿：`approver: TODO`，`status: pending`，理由标明「待守门人批准」。
2. 守门人（验证，`waivers/approvers.yml` 中的 login）书面批准后，把条目移入 `waivers/<check>.yml`，填写 `approver`、`approved_date`、`review_when`。
3. 脚本**只认带批准人且批准人是守门人**的条目；`TODO` / 空 / 非守门人 / `draft` 一律忽略。
4. `.github/CODEOWNERS` 把 `waivers/`、`gate/`、`.github/workflows/gate.yml` 的审批指给仓库 owner `lukebest`。

`gate/handwritten.yml`、`gate/stubs.yml`、`gate/hooks_ports.yml` 的条目字段与豁免相同：路径或模块、原因、批准人、日期、复查条件。

D10 leftover **不要**靠豁免放行：用 `gate/legacy.txt` 做报告-only。新叶子一律拦截，只能走本流程豁免。

覆盖率具名 waiver（如 `WAIVER_CRD_UF_*`，CODING_STYLE §7）仍归验证计划，不是本门禁 YAML。

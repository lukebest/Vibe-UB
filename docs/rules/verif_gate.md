## 0. 流水线与本地入口

每次 `push` / `pull_request` 跑 `.github/workflows/gate.yml`。CI **只**调用 `scripts/gate/*.sh`。本地：

```
make gate
```

与 CI 同一套脚本。快速综合的 QoR 趋势归实现（`scripts/impl/quick_synth.sh`），**不**拦合入；本门禁的 `synth-check` 只判过 / 不过（latch / 多驱动 / 组合环）。

工具版本**只**从仓库根 `TOOLCHAIN.lock` 读。出现第二份 `TOOLCHAIN.lock` 记 `TOOLCHAIN_LOCK_CONFLICT`（拦截）。装不到锁定版本时，job 日志打印 `locked=` 与 `actual=`，并写明 MISMATCH，不静默当成已锁定。

机器可读名单在 `scripts/gate/`（与 `waivers/` 同一套批准约束：`approver` 必须是 `waivers/approvers.yml` 里的守门人）。`waivers/pending/` 草稿只展示、不生效。

## 0.1 三线与自动发现

层名从目录发现，脚本不写死 `pcs` / `dll` / `lmsm` / `csr`。枚举必须包含 `cmn`（Xia / PR #21：统一存储叶子 `ub_cmn_mem_1r1w`）。B/C 以后加 `pycircuit/<layer>/`、`rtl/<layer>/`、`formal/<iface>/`、`tb/<layer>/` 即可被扫到。不扫 `rtl/gen/`。

SPEC §2.2 变体：同一叶子多组参数 → `rtl/<layer>/<叶子>_<标签>.v`；单组不加标签；`_placeholder` 只 lint/TB。存储原语标签定为 `d<DEPTH>w<WIDTH>[m<WMASK_W>]`（例：`ub_cmn_mem_1r1w_d512w512m64`、`ub_cmn_mem_1r1w_d64w64m16`）。

| 线 | 检查 | 路径 |
| --- | --- | --- |
| **A** | emit_rtl.py 重生成到临时目录后与提交的 `rtl/<层>/`、`rtl/<层>/hooks/` 逐字节比对 + hooks 存在 + 端口一致性 + PRODUCT≡HOOKS + 来源 | `pycircuit/<layer>/` → `scripts/emit_rtl.py` → `rtl/<layer>/` 与 `rtl/<layer>/hooks/` |
| **B** | lint / synth-check / cdc-rdc | `rtl/<layer>/`（含 `hooks/`）；白名单手写与已登记 stub/macro 照常跑 |
| **C** | `formal/<iface>/*.sby` | 每接口自带小桩，无产品 RTL 也能跑。`formal/cmn/` 自动发现。未选型 SRAM 宏用 `blackbox.yml` 的 `stub`/`macro`，见 §1.2 |

`ub_cmn_mem_1r1w` 走 pycc 生成：源码 `pycircuit/cmn/`，输出 `rtl/cmn/`，按普通叶子处理（来源检查、pycc 重生成、eqy）。

门禁不自己拼 pycc 命令，只调用 `scripts/emit_rtl.py`（`compile()` + `pycc --emit=verilog --logic-depth=64`，参数以该脚本为唯一来源）。pycc 按仓库根 `TOOLCHAIN.lock` 安装（pyCircuit `43cc5918…` / `pyc4.0` / LLVM 19）。重生成到临时目录后与提交的 `rtl/<层>/`、`rtl/<层>/hooks/` 逐字节比对。`emit_rtl.py` 不存在，或 pycc 仍装不上：该项 **skip（不拦）** 并写明原因；脚本在且工具链可用则拦。手写扫描、hooks、等价、大网表清单、`pyc_*` 扫描仍跑。

超阈值变体（`docs/rules/impl_quick_synth.md`，默认 4096 bit）不提交 `.v`，写入 `rtl/<层>/manifest.yml`（变体名、参数、pycc 版本、PRODUCT/HOOKS sha256）。门禁能再生时核 sha256、端口，以及两份网表除模块名外逐字节一致。超阈值却提交了 `.v`、或清单有条目却生成不出，均拦截。

`rtl/pyc_lib/` **等 #21 合入才出现**。目录在就按锁定 pyCircuit 逐字节比对；缺了只报告跳过，不失败。其它目录出现 `pyc_*` 原语仍拦截。`handwritten.yml` 里的 `pyc_reg` 临时项由 #21 自己撤，本分册不撤。

### 0.2 导入根与 `lib/`（SPEC §2.2 已定）

调用 pyCircuit 叶子（`pycircuit.cli emit`、`scripts/emit_rtl.py`、以及会 `import` 叶子的 tb-selfcheck）时：

- `PYTHONPATH` **最前面**是 `<repo>/pycircuit`。叶子写 `from <层>.lib import ...`（例：C 线 #27 `from mem.lib import ...`）。
- **仓库根不得进 `sys.path`**。仓库的 `pycircuit/` 目录与已安装的 pyCircuit 库包同名，根在路径上会遮住安装包（#27 上表现为 `Python package pycircuit is not importable`）。`<repo>/pycircuit` 本身在 `PYTHONPATH` 上不是遮蔽，而是导入根；缺了它则 `from mem.lib` 报 `No module named 'mem'`。
- 一律用脚本路径调用，不用 `python -m`；`python -P` / `PYTHONSAFEPATH` 让 cwd 不进路径。
- 叶子只扫 `pycircuit/<层>/*.py`，跳过 `pycircuit/<层>/lib/` 和 `__init__.py`。`lib/` **不生成网表**，但仍跑「禁止拼接 Verilog 文本」静态扫描。层根目录下的 `.py`（即使是 helper）按叶子处理。

命中仓库根进路径记 `IMPORT_ROOT_SHADOW`，拦截。

## 1. 共同失败判据

每条检查产出 findings。每条 finding 先分类，再看豁免：

| 栏 | 判定 | 门禁 |
| --- | --- | --- |
| 新叶子 | 不在 `scripts/gate/legacy.txt`，或文件头表明由 pyCircuit 生成 | **拦截**（未豁免即 FAIL） |
| D10 legacy | 路径匹配 `scripts/gate/legacy.txt`，且不是 pyCircuit 重写 | **只报告不拦截** |
| 迁移待办 | `scripts/gate/pycircuit_migrate.txt`：main、PR #5 / #7 / #12，以及 PR #11 的 `pycircuit/csr/ub_csr_regs.py`（状态「已迁」） | **只报告不拦截** |
| report-only | 桩时序 vs MODULE_INVENTORY、组合逻辑级数、`emit_rtl.py` 缺失 / pycc 装不上时的 emit skip、`rtl/pyc_lib/` 尚未落地 | **只报告不拦截** |

D10 判定见 [DECISIONS.md](../DECISIONS.md) D10。`scripts/gate/legacy.txt` 是可配置名单（精确路径或 glob）。从名单删路径 = 该文件改为拦截，须守门人书面批准（CODEOWNERS 覆盖 `/scripts/gate/*.txt`）。**删文件本身归设计清理 PR**；本门禁只按「待删除」名单出报告：名单或迁移名册里的路径若已不存在，标「已删除」并从 `total` / backlog 扣除，**不报错、不删、不改这些文件**。

pyCircuit 生成物即使暂时仍写在旧路径，只要文件头含 `GENERATED from pycircuit` / `Generated by`，一律当新叶子拦截。

豁免见 §9。未豁免的新叶子 finding 使对应 job 失败。legacy / report-only 栏写入报告，不构成 FAIL。

### 1.1 白名单手写 SV（`scripts/gate/handwritten.yml`）

与 `waivers/` 同一套约束：每条写文件路径、原因、批准人（守门人）。今天只有 `rtl/common/ub_rst_sync.sv`（复位同步器，CODING_STYLE §3，SPEC §4.2，D6）。

清单上的文件：

- 不参与 emit 一致性检查和「必须有 hooks 网表」检查
- eqy / Yosys 等价跳过（`TEST_HOOKS=0/1` 共用同一份）
- lint、综合检查、CDC/RDC 照常跑
- CDC 把它当作合法的复位同步单元（可含异步复位敏感表，计入 sync cell）

不在清单上的手写 `.v` / `.sv` 出现在 `rtl/` 记 `HANDWRITTEN_UNLISTED`。新叶子拦截；若路径同时在 `scripts/gate/legacy.txt` 则只报告。白名单单元本身不进 `legacy.txt`，其上的 lint / CDC finding 按新叶子拦截。

### 1.2 桩 / 黑盒（`scripts/gate/blackbox.yml`）

C 线用行为模型桩代替尚未选型的 SRAM 宏。`kind` 只允许 `stub` | `macro`（`macro` 留给以后换 SRAM 宏）。**去掉 `primitive`。**

Xia：统一存储原语 `ub_cmn_mem_1r1w` 走 pycc 生成，源码 `pycircuit/cmn/`、输出 `rtl/cmn/`，按普通叶子处理（来源检查、pycc 重生成、小变体等价），**不要**登记进 `blackbox.yml`。大实例（depth×width 超 `impl_quick_synth.md` 阈值，默认 4096 bit）在上层 synth-check / 等价中当黑盒，两边同一份；见 §3 / §6。

每条字段（缺字段或 `approver` 空则清单校验失败）：`module` / `file` / `kind` / `replaces` / `depth` / `width` / `ports`（`1RW`\|`1R1W`） / `read_latency` / `rw_conflict`（`old`\|`new`） / `reset` / `macro` / `reason` / `registrant` / `approver`。阵列不复位时必须 `valid_outside: true`，否则 RDC 拦截。

- **已登记 stub：** lint 照常跑；synth-check 用 `read_verilog -lib` 当黑盒
- **已登记 macro：** 同上，留给真实 SRAM 宏
- **未登记**的桩或黑盒（`(* blackbox *)` / `(* stub *)`、文件名 `*_stub` / `*_blackbox`、目录 `stubs/` / `blackbox/`）：`STUB_UNLISTED`，**拦截**

桩时序以 **MODULE_INVENTORY** 存储需求行为为准（架构所有；落地路径优先 `docs/arch/MODULE_INVENTORY.md` / `.yml`）：

| 项 | 约定 |
| --- | --- |
| 读延迟 | `read_latency`（addr→data 的 `core_clk` 拍数） |
| 端口 | `1RW` 或 `1R1W` |
| 同地址冲突 | `old` 或 `new` |

自动对照是 **report-only**（`STUB_TIMING`）。清单尚未有条目、库存文件尚未落地时，打印原因并跳过对照。

## 9. 豁免流程

任何检查豁免都需要守门人**书面批准**（[TEAM.md](../TEAM.md) §4）。不得自己批自己的草稿。

1. 在 `waivers/pending/` 写 YAML 草稿：`approver: TODO`，`status: pending`，理由标明「待守门人批准」。
2. 守门人（验证，`waivers/approvers.yml` 中的 login）书面批准后，把条目移入 `waivers/<check>.yml`，填写 `approver`、`approved_date`、`review_when`。
3. 脚本**只认带批准人且批准人是守门人**的条目；`TODO` / 空 / 非守门人 / `draft` 一律忽略。
4. `.github/CODEOWNERS` 把 `waivers/`、`scripts/gate/`、`.github/workflows/` 的审批指给仓库 owner `lukebest`。非守门人 PR 改 `waivers/` 时，守门人须在 PR 评论里写一行 `GATE-WAIVER-APPROVED: waivers/<file>.yml`（见 §11 GATE-OWNED-PATHS）。守门人 PR 的标题必须以 `gate:` 开头。

D10 leftover **不要**靠豁免放行：用 `scripts/gate/legacy.txt` 做报告-only。新叶子一律拦截，只能走本流程豁免。

覆盖率具名 waiver（如 `WAIVER_CRD_UF_*`，CODING_STYLE §7）仍归验证计划，不是本门禁 YAML。

## 12. PR 审查清单（人工，不自动拦截）

合入前审查人勾选。门禁脚本不根据本清单 FAIL。

### 成对模块 TB（GATE-TB-PAIR-001）

适用于分发/收集、编码/解码、加扰/解扰、TX/RX：

- [ ] 每一侧都有独立的 `model/` 参考逐位比对（不是只跑 A→B 自环）
- [ ] 有能锁定方向的定向用例（one-hot 扫描、递增数据）
- [ ] 自环 / loopback 若存在，只作补充，不是唯一检查

A 线 lane dist 反例：只做分发再收集自环时，条带方向反了仍能过。

### 记分板比对次数（GATE-TB-SB-001）

适用于所有接入记分板的用例（unit / subsys / top）：

- [ ] 记分板累计实际比对次数（每次 compare 计 1；分段比对按段统计；跳过的激励不计）
- [ ] 测试结束断言比对次数 `> 0`（空测不得 PASS）
- [ ] 测试结束断言比对次数等于该用例声明的预期次数（少比不得 PASS）

反例：激励全被 `if` / `skip` 掉，记分板 0 mismatch、0 compare，仿真仍显示通过。

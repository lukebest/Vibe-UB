## 0. 流水线与本地入口

每次 `push` / `pull_request` 跑 `.github/workflows/gate.yml`。CI **只**调用 `scripts/gate/*.sh`。本地：

```
make gate
```

与 CI 同一套脚本。快速综合的 QoR 趋势归实现（`scripts/impl/quick_synth.sh`），**不**拦合入；本门禁的 `synth-check` 只判过 / 不过（latch / 多驱动 / 组合环）。

工具版本从仓库根 `TOOLCHAIN.lock` 读。装不到锁定版本时，job 日志打印 `locked=` 与 `actual=`，并写明 MISMATCH，不静默当成已锁定。

## 1. 共同失败判据

每条检查产出 findings。每条 finding 先分类，再看豁免：

| 栏 | 判定 | 门禁 |
| --- | --- | --- |
| 新叶子 | 不在 `scripts/gate/legacy.txt`，或文件头表明由 pyCircuit 生成 | **拦截**（未豁免即 FAIL） |
| D10 legacy | 路径匹配 `scripts/gate/legacy.txt`，且不是 pyCircuit 重写 | **只报告不拦截** |

D10 判定见 [DECISIONS.md](../DECISIONS.md) D10：现有手写 `rtl/` / `tb/` 将迁 `legacy/`，不属于 pyCircuit 重新生成的部分。`legacy.txt` 是可配置名单（精确路径或 glob）。从名单删路径 = 该文件改为拦截，须守门人书面批准（CODEOWNERS 覆盖该文件）。

pyCircuit 生成物即使暂时仍写在旧路径（例如 PR #5 覆盖 `rtl/pcs/ub_pcs_scrambler.v`），只要文件头含 `GENERATED from pycircuit` / `Generated by`，一律当新叶子拦截。

白名单手写单元（`ub_rst_sync` 等，CODING_STYLE §3）不进 `legacy.txt`，按新叶子拦截。

豁免见 §8。未豁免的新叶子 finding 使对应 job 失败。legacy 栏写入报告，留给 legacy 迁移 PR 与守门人，不构成 FAIL。

## 4. cdc-rdc

M1 单时钟 `core_clk`（SPEC §4.1）。`rst_n` 异步置位、同步释放，进入点必须经 `ub_rst_sync`（2 级）再经 `ub_pyc_rst_adapt` 得到 `rst_pyc`（SPEC §4.2，CODING_STYLE §2）。

规则写在 `scripts/gate/cdc_rules.yml`，可加时钟名、同步器单元、新 check id，不必改 workflow。

| ID | 规则 | 失败条件 | 来源 | 日期 |
| --- | --- | --- | --- | --- |
| GATE-CDC-001 | 单时钟 | 模块出现多个时钟口，或出现 `pma_clk` | SPEC §4.1 | 2026-10-10 |
| GATE-CDC-002 | 时钟名 | 时钟口不是 `core_clk` | SPEC §4.1 | 2026-10-10 |
| GATE-CDC-003 | 异步复位进入点 | `always @(posedge … or negedge …)` 出现在 `ub_rst_sync` 以外 | D6；CODING_STYLE §2 / §3 | 2026-10-10 |
| GATE-CDC-004 | `rst_n` 入口 | 带 `rst_n` 的时序模块未实例化 `ub_rst_sync` | SPEC §4.2 | 2026-10-10 |
| GATE-CDC-005 | 异步 / 非 `core_clk` 输入 | 命中 `async_input_regex` 的输入未进 2 级同步器 | CODING_STYLE §2 | 2026-10-10 |

现有检查 id：`CLOCK_MULTI`、`CLOCK_NOT_CORE`、`CLOCK_FORBIDDEN`、`RST_ASYNC_NOT_VIA_SYNC`、`RST_SYNC_MISSING`、`ASYNC_INPUT_UNSYNC`、`SYNC_STAGES`。

**失败判据：** 新叶子上出现未豁免的上述 id。legacy（当前手写 `clk` + `or negedge rst_n`）只报告，不拦合入。

## 8. 豁免流程

任何检查豁免都需要守门人**书面批准**（[TEAM.md](../TEAM.md) §4）。不得自己批自己的草稿。

1. 在 `waivers/pending/` 写 YAML 草稿：`approver: TODO`，`status: pending`，理由标明「待守门人批准」。
2. 守门人（验证，`waivers/approvers.yml` 中的 login）书面批准后，把条目移入 `waivers/<check>.yml`，填写 `approver`、`approved_date`、`review_when`。
3. 脚本**只认带批准人且批准人是守门人**的条目；`TODO` / 空 / 非守门人 / `draft` 一律忽略。
4. `.github/CODEOWNERS` 把 `waivers/`、`.github/workflows/gate.yml`、`scripts/gate/legacy.txt` 的审批指给仓库 owner `lukebest`。

条目字段：`id`、`check`、`module` / `file`、`rule` / `message` 匹配、`reason`、`approver`、`approved_date`、`review_when`（到期或复查条件）。

D10 legacy **不要**靠豁免放行：用 `legacy.txt` 做报告-only。新叶子一律拦截，只能走本流程豁免。

覆盖率具名 waiver（如 `WAIVER_CRD_UF_*`，CODING_STYLE §7）仍归验证计划，不是本门禁 YAML。
